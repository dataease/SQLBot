# 安全 Agent 说明

## 原则

- LLM 输出、SQL、文件名、路径、Host 头、路由参数、第三方回传数据和前端消息都不是可信输入。
- 新接口默认拒绝；先认证、再授权、再校验资源归属，最后执行业务。
- 发现现有绕过路径时优先收敛授权语义，不要只在单个 URL 上打补丁。
- 涉及以下任何区域，必须补充或更新回归测试，并运行 `backend/tests/` 中的相关守卫。

## API 权限

- 使用 `CurrentUser` / `SessionDep` 获取身份和会话，不信任请求体中的用户或工作空间 ID。
- 资源型接口使用 `@require_permissions(...)`，并确认：
  - `type` 指向正确资源；
  - `keyExpression` 能取到真实资源 ID；
  - 列表语义不会被单个资源绕过；
  - 管理员、工作空间管理员和普通用户路径都明确。
- 权限表达式引用的参数缺失、解析失败或归属不匹配时必须拒绝，不能回退为直接执行处理函数。
- 子资源归属从服务端记录推导并校验完整关系（如字段 → 表 → 数据源 → 工作空间）；请求中的 `ds_id`、`oid` 仅为待校验输入。不能仅验证调用者有权访问所提供的数据源，再按任意表/字段 ID 执行操作。
- 批量接口明确整批拒绝还是仅操作有权记录，并测试混合归属输入；单项、批量、同步、导出等入口应遵循相同授权边界。
- 手写查询归属时，同时校验：
  - 资源存在；
  - 资源属于当前工作空间；
  - 资源属于当前用户或其授权范围；
  - 助手上下文没有切换到其他工作空间。
- `oid` 和 `workspace_id` 都表示工作空间 ID；不要把两者当成不同授权域。
- 高级助手动态数据源只允许既有动态类型走动态数据源例外；本地 `CoreDatasource` 仍必须校验工作空间归属。

## SQL 生成与执行

修改主流程时应满足以下安全顺序；需在实际入口和调用链验证，不能把本清单当作现状已安全的证明：

1. 只把允许的表和字段元数据提供给模型；
2. 解析模型返回 JSON 并提取 SQL；
3. 用 `sqlglot` 提取真实表名并排除 CTE 别名，无法提取表名时始终拒绝；
4. 默认对照允许表集合拒绝未授权表；部署显式设置 `SQLBOT_SKIP_TABLE_CHECK=true` 时，仅跳过本步；
5. 按用户、助手和页面嵌入场景应用行权限或动态 SQL 变换；
6. 校验并保存最终 SQL；
7. 执行最终 SQL 并保存结果。

额外要求：

- 不要信任模型返回的 `tables` 字段替代真实 SQL 解析。
- 行权限拼接沿用白名单逻辑运算符和 `_escape_sql_value`，不要引入新的字符串拼接入口。
- 保持 SQL 行数限制和 `SQLBOT_ALLOW_METADATA_QUERIES` 默认关闭语义；不要为了调试全局开启元数据查询。
- `SQLBOT_SKIP_TABLE_CHECK` 默认为 `false`，仅在启动时读取，不提供参数页面或运行时修改。开启后可能访问数据源账号可读取的未勾选表；SQL 只读、危险函数、元数据查询控制与既有权限处理不随此开关关闭。配置方式见 [`backend/README.md`](../../backend/README.md)。
- 动态 SQL 生成后仍必须走同一解析、校验和保存路径。
- 数据源连接配置在服务端解密。完整配置、凭据和存储密钥不得进入日志或 API 响应。编辑详情的字段边界见「数据源配置存储」。

## 认证、Host 与嵌入

- 修改 `backend/main.py` 的中间件顺序时，验证实际请求执行顺序（不能只看注册顺序）；`HostValidationMiddleware` 必须在认证/业务使用 Host 前拒绝非法值，并回归预检与正常请求。
- Host 只允许合法域名 / IPv4 / IPv6 形态，不能包含 `/`、`@` 或空白。
- 认证和助手 token 头由后端中间件与前端 request interceptor 处理；不要新增手工传递或复制 token 的路径。
- 页面嵌入协议必须保持：
  - 仅 `AssistantModel.type == 4` 可用 embedded 协议；
  - 先提取目标助手，再用 `app_secret` 验证签名；
  - 管理员账号拒绝通过 embedded token 使用；
  - 账号状态和工作空间归属仍需校验。
- 修改助手 `domain`、`app_id`、`app_secret` 或类型时，同时考虑目标系统信任边界和跨工作空间访问。
- 前端 `postMessage` 证书流程不要降级为无请求绑定、无来源约束或永久有效证书。

## 文件与路径

- 不信任上传文件名、扩展名、MIME、sheet 名或用户提供的 `filePath`。
- 上传必须限制类型和大小，落盘使用服务端生成的文件名或 opaque ID。
- 读取用户可控路径前，解析真实路径后用 `os.path.commonpath` 等验证其仍位于允许目录内，或通过已授权的内部 ID 映射路径；不使用字符串前缀判断。校验到打开之间不得允许不可信方替换路径或符号链接。
- 下载前先校验权限和服务端文件实际路径的目录归属，包括符号链接解析；`os.path.basename` 只适合清理下载展示名，`FileResponse` 只负责传输，两者都不能替代路径授权。响应不回显内部绝对路径。
- Excel/CSV 解析错误不能变成可猜测的内部路径信息。

## 前端渲染

- 不直接在组件中调用 axios，避免绕开认证、语言、助手证书和错误处理。
- Markdown 渲染保持 `html: false`，代码高亮必须转义。
- 新增富文本 / HTML 渲染必须走既有安全工具和组件；不要添加未净化 `v-html`。
- 链接、图片和远程脚本必须限制协议和来源，不允许 `javascript:` 或用户控制的服务端地址。
- xpack 静态脚本保留缓存穿透参数和失败处理；不要把商业脚本或密钥复制进前端源码。

## 日志与敏感信息

- 不记录 token、密码、API key、数据源明文连接串、SQL 凭据、助手 secret 或完整敏感配置。
- 异常响应面向用户时使用后端 i18n 错误；内部 traceback 只进入受控日志。
- 安全测试样本可以包含攻击载荷，但不得包含真实可用凭据或内部地址。

## 必测场景

按本次涉及的入口选择相关场景；不要求每次安全改动执行下列全部类别，但必须说明未覆盖的相关风险：

- 未登录、无权限、资源不存在、跨工作空间访问；
- 管理员、工作空间管理员、普通用户、助手用户；
- Host 头携带路径、`@`、空白等污染形态；
- SQL 引用未授权表、CTE 别名、动态 SQL 和行权限边界；
- embedded token 错误助手类型、错误签名、管理员账号和无效账号；
- 上传路径穿越、非法扩展、超限大小和重复扩展名；
- 前端错误传播和未净化内容渲染。

## 本地密码凭据

- 统一存储/校验入口为 `backend/common/core/passwords.py`。新密码使用 Argon2id（19 MiB、2 次迭代、并行度 1、16 字节随机盐）；传输 RSA 与持久化哈希是独立机制。
- 裸 MD5 仅用于历史读取兼容。迁移 `075_local_password_hashes.py` 分页读取并通过条件更新包装为带版本前缀的 Argon2id(MD5)，每次写入独立提交，可在中断后重跑。不要用配置的初始密码覆盖数据库现有凭据。
- 本地及 MCP 密码登录通过资格校验后，历史凭据升级为直接 Argon2id；条件更新避免覆盖并发重置。初始密码判断必须验证候选密码，不比较摘要是否相等。
- 初始化、创建、导入、重置、改密必须生成新的随机盐哈希；密码摘要不得进入 API 响应、token 或日志。未知或损坏格式拒绝认证，不尝试其他算法兜底。
- 上线先备份并停止旧版本写入，统一升级所有 API/MCP 实例，再执行迁移和启用新服务；不支持新旧程序混跑。迁移 downgrade 保留强哈希，不能恢复原 MD5；回退旧程序需要协调恢复升级前备份（评估后续业务数据损失）或受控重置，不能只回退二进制。旧备份可能仍含裸 MD5，迁移不能撤回已泄露凭据。
- 大用户量部署先在同规格隔离环境测量登录并发、内存和迁移耗时；不要为提升速度降低参数。登录哈希在线程池执行；数据库迁移中的计算同步执行且不持有长期行锁。

## 数据源配置存储

- 服务端使用部署独立的 AES-256-GCM 密钥，默认首次启动在持久化的 `UPLOAD_DIR/.secrets` 内生成密钥，可通过 `SQLBOT_DATASOURCE_KEYS_FILE` 指定已有的受控密钥文件。公开的旧 ECB 密钥用于启动迁移及解析历史浏览器请求编码。
- 列表和写入响应省略配置。授权编辑详情只返回表单所需的字段，省略密码；额外连接参数向有权编辑的用户回显，允许修改或清空。编辑时连接目标不变且密码字段缺省表示保留原密码；连接目标变化且密码字段缺省时使用空密码，不沿用旧目标凭据。测试连接与更新沿用已存凭据时必须核对工作空间和连接目标。
- 启动迁移、备份恢复和密钥轮换见 [后端运行说明](../../backend/README.md#数据源存储密钥)。

## 数据源 Kerberos

Hive/Impala 上传的 krb5.conf 和 keytab 随数据源配置加密保存，编辑详情不回传；改变认证目标时重新提供凭据。配置文件必须通过 apps/db/kerberos_connection.py 的受限解析，禁止文件包含、插件和客户端指定服务器文件路径。认证在独立工作进程中执行，不修改请求服务进程的 Kerberos 环境或共享身份缓存。当前每次连接重新获取票据，结束时销毁临时缓存，不复用 Kerberos 长连接池；部署与验收边界见 backend/README.md。

## 本地账号绑定第三方身份

- 绑定业务在 xpack 的 `authentication/bindings.py`、`binding_providers.py`；共享存储契约在 `apps/system/models/user.py`，由主工程 Alembic 迁移管理。
- 个人信息基本信息页对本地及非本地登录用户开放；非本地账号不展示账号绑定标签或请求绑定列表。已登录的本地用户（包含内置系统管理员）只能管理自己的绑定；助手和 API Key 凭据不可调用。用户 ID 来自认证上下文，账号、角色、工作空间及本地账号来源不因绑定而改变。
- 本地密码验证复用统一凭据入口；同一用户的绑定与解绑共用五分钟十次密码验证额度，成功与失败均计数。二维码刷新在原请求记录上轮换随机 state，不新增密码尝试、不清空额度或延长到期时间；旧 state 不再可用，查询可能返回不存在。请求同时绑定原登录 token、当前密码凭据和认证配置，五分钟有效。确认时重新校验用户、配置和唯一归属；数据库唯一约束处理并发冲突。不按同名账号或邮箱自动绑定，不合并已有独立平台用户。
- 第三方认证仅获取身份，不创建 SQLBot 用户、不签发或替换当前登录 token；认证完成必须由用户再次确认才落关联。授权码、票据、第三方 token 和密码不得落入请求表、审计或响应。认证配置的账号映射必须选择平台内稳定且唯一的身份字段；更换配置后显式绑定失效，要求重新验证绑定。
- 回调通知仅是唤醒信号；原页面以已认证的请求读取后端状态。校验消息 origin、source 与本次随机 state；取消、刷新、超时、重放或修改密码后的旧回调均不得绑定。绑定回调在独立页面处理，保留原有正常登录页面与跳转规则。
- 开源版默认只展示个人基本信息；绑定标签与新增能力以后端能力接口为准，不依据许可证报错猜测。无有效许可证时列表只返回本人历史绑定，仍允许解绑；禁止新增及确认绑定。解绑验证本地密码后只删除本人关联；停用平台或许可证失效仍可解绑。解绑影响后续身份登录，不撤销全部已签发会话。绑定与解绑审计和关联写入使用同一事务。

LDAP 账号绑定在验证本地密码后使用独立凭据步骤，不调用普通登录接口或替换会话；目录密码仅在一次认证调用中使用，不持久化。绑定与 LDAP 登录使用同一认证源账号映射，目录搜索输入必须转义，验证后关闭连接。国际飞书不再开放新增绑定，历史关联仍允许本人验证密码后解除。
