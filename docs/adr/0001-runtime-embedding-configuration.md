# 向量召回策略采用系统级运行时配置

系统管理员在参数配置页面统一管理知识召回、表筛选和数据源预筛选的策略参数。向量模型及模型目录继续作为部署配置，不在本次引入模型切换；模型切换涉及已有向量兼容与重建，不能按普通召回参数处理。配置适用于所有工作空间，各入口仍遵循自身的功能和知识作用域。

有效值按“已保存的界面值 > 启动配置 > 代码默认值”解析，页面显示后端解析出的有效值。未保存过的参数沿用已有部署配置，保存后由持久化值覆盖。术语和 SQL 示例分别配置相似度与候选数量，不增加一层公共默认值继承。

配置保存后无需重启，从各服务进程的下一次问数或后台任务开始生效；任务开始时取得配置快照，执行期间保持一致。关闭开关允许已开始的向量生成任务完成，避免一次问数的筛选规则中途变化。

开关同时控制向量生成与向量召回。关闭期间不开始新的向量生成，但内容修改必须使旧向量失效；重新开启后异步补齐缺失或失效向量，保留未失效的向量。仅在开启时扫描空向量无法覆盖关闭期间修改过的已有数据。

向量补齐期间保持问数可用：知识召回保留字面匹配及已有有效向量；候选表或数据源的向量不完整时，跳过该层向量预筛选，保留原本可访问的候选集合。接受暂时增加上下文与耗时，以避免不完整向量提前排除候选。

保留现有开关关系和召回语义。新的页面保存严格校验相似度和权重为 `[0,1]` 内有限数值、数量为正整数，非法输入整次拒绝保存；不顺带改变既有启动配置解析行为。

本决策已由 `common/core/embedding_config.py` 的统一类型与直接持久化读取、`LLMService` 任务快照，以及 `embedding_lifecycle.py` / 数据源任务的资源锁和条件写回实现。保存使用参数写入事务锁，后台任务在工作线程开始时读取有效配置；不依赖 xpack 的进程内参数缓存传播。实现状态不等同于所有部署环境均已验收；完整参数、调用链、可重复验证与剩余范围见[设计与影响范围](../design/embedding-parameter-configuration.md)。

表与数据源采用完整块集合后，完成标记是 `metadata_embedding` 中与当前输入、部署模型和格式版本一致且完整的表示，旧 `embedding` 字段不参与完成判断。迁移只准备结构；`main.lifespan` 在迁移成功后提交后台扫描，启动无需等待模型编码。启动、重新开启和资源保存统一进入 `common/utils/metadata_scheduler.py`：每个进程一个元数据工作线程，一个执行批次与一个合并的待执行批次；待处理资源 ID 超过容量时转为完整扫描。扫描按 ID 游标分页，以启动扫描时最大 ID 为上界；扫描期间的新保存仍排入下一批。配置在每批实际开始时读取，同批表与数据源共享快照。知识任务继续使用原有调度路径。

该调度以吞吐量换取可控的模型并发与积压内存，不持久化“扫描完成”状态。跨进程仍靠资源事务锁串行；输入变动、失败或中断后通过当前块集合的有效性决定重试，已完成且仍有效的资源不会重新编码。每资源有限重试失败后保留未完成状态并报告；其余资源继续处理，后续资源任务、重新开启或重启可恢复。补齐期间继续沿用上述合法候选回退语义，接受完整候选上下文带来的临时开销。

升级部署顺序：先停止所有旧版本服务及后台写者，再启动新版本，让正常启动迁移准备结构并提交后台补齐。旧版本写者不维护新块集合的失效契约；本实现没有验证或承诺新旧版本滚动混跑。多进程恢复测试仅覆盖同一新版本。合成模型、合成元数据与真实数据库回归不能替代客户数据、真实关键词提取和完整 SQL 问数验收。
